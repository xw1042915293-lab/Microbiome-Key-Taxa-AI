# 项目文档索引

本目录文档分为“V1.0 申报与交付材料”“研究与答辩辅助材料”和“历史开发记录”三类。软件名称、版本和术语统一以 `SOFTWARE_PROFILE.md` 为准。

## 1. V1.0 申报与交付材料

| 文档 | 用途 |
|---|---|
| `SOFTWARE_PROFILE.md` | 软件基本信息、统一术语和版本检查清单 |
| `SOFTWARE_COPYRIGHT_SUBMISSION.md` | 软著申报概述、技术特点和提交材料清单 |
| `SYSTEM_REQUIREMENTS.md` | 系统应满足的功能、数据和非功能需求 |
| `SYSTEM_DESIGN.md` | 系统架构、模块、流程、存储和异常设计 |
| `USER_GUIDE.md` | 安装、输入准备、页面操作和结果解释 |
| `TEST_REPORT.md` | 当前验证事实、已知问题和最终验收要求 |
| `final_acceptance_summary.md` | V1.0 总体验收状态摘要 |

## 2. 研究与答辩辅助材料

| 文档 | 用途 |
|---|---|
| `INNOVATION_POINTS.md` | 工程特点、创新点和表述边界 |
| `METHODS_DESCRIPTION.md` | 各分析模块的方法与公式说明 |
| `CASE_STUDY.md` | 示例数据流程及结果阅读口径 |
| `DEMO_CASE.md` | 现场演示操作提纲 |
| `PAPER_OUTLINE.md` | 论文结构建议 |

这些材料应在 V1.0 最终验收后补充同一正式任务的截图、任务编号和实际结果，不得沿用失效的历史任务路径。

## 3. 历史记录处理

早期 Phase 3—8 验收碎片引用了已经失效的任务目录，且不能代表 V1.0 当前状态，已从工作目录清理。需要追溯时可通过 Git 历史查看。

## 4. 文档维护规则

- 需求说明只写“系统应做什么”，不混入当前测试结论；
- 设计说明只写架构与实现机制，不承担用户教程；
- 用户手册按界面操作顺序组织，不夸大统计结果；
- 测试报告只记录实际执行和可以核验的事实；
- 历史记录不删除，但必须与当前版本结论明确区分；
- 软件名称、版本、功能名称和解释边界在所有材料中保持一致。
