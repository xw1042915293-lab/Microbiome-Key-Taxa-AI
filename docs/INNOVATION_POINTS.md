# 创新点与差异说明（INNOVATION POINTS）

本文档用于硕士论文/开题材料中的“创新点”撰写。为避免夸大，以下表述以 **工程化整合与风险控制** 为核心，不将系统描述为替代 microeco 2.0 的新算法平台。

## 创新点 1：基于 microeco 2.0 的自动化微生物组再分析流程
要点（偏工程创新）：
- 以 microeco 2.0 作为分析底座，构建上层应用系统，将常见分析环节（Alpha/Beta/Diff/ML/Network/报告）串成标准化流程。
- 通过 Shiny 交互减少脚本门槛：Upload -> Data Check -> Parameters -> 一键运行 -> 报告输出。
- 将结果统一落盘到 job 目录，形成“可追溯产物集合”，便于复盘与展示。

边界说明：
- microeco 负责核心数据结构与部分计算，本系统负责编排与产物组织，不宣称提出新的统计方法。

## 创新点 2：结构化统计结果约束的大语言模型解释框架
动机：
- 传统“直接把原始表喂给 LLM 生成解释”存在显著风险：幻觉、泄漏原始数据、把不显著结果写成显著、给出因果结论等。

本系统做法（可信解释的约束点）：
- 解释输入被限制为：结构化统计 JSON（如 diff_summary）+ 本地规则解释文本（Phase 4A）。
- 在提示词中明确约束：
  - 只能使用提供的统计结果与本地解释；
  - 不得引用原始 abundance；
  - 不得改变统计结论、不得“升格显著性”；
  - 不得推断因果或机制；
  - 输出为结构化 JSON（便于审计与回放）。
- 保存请求/响应留痕（json）与输出文本（md），满足可审计与可追溯。

边界说明：
- AI 输出是受约束的摘要/写作辅助，不作为生物学因果证据，也不替代人工审阅。

## 创新点 3：差异分析、机器学习和网络中心性联合的 Key Taxa Score
动机：
- 单一证据（仅差异或仅重要性）可能受样本量、噪声、阈值等影响；工程上常需要“多证据合并的候选优先级”。

本系统做法：
- 将三类证据分别归一化：差异显著性与效应量（FDR 与 |log2FC|）、随机森林特征重要性、网络中心性（degree + betweenness）。
- 采用可解释的加权平均进行融合；当某类证据缺失时自动调整权重，并按“每个 taxon 实际可用证据”计算分母，避免因 NA 导致分数不可用。
- 输出 Top20 与推荐等级（High/Medium/Low）用于演示与候选筛选。

边界说明（必须强调）：
- Key Taxa Score 是工程化排序指标，属于候选优先级建议；不等价于生物学因果“关键菌”证明。
- 机器学习与网络证据为探索性结果，需结合实验设计与外部证据进一步验证。

## 创新点 4：可复现 HTML 报告生成
要点：
- 以 Quarto 模板化渲染报告，将 job 目录中的 tables/figures/json/ai 产物统一编排到 `report.html`。
- 报告生成与分析结果强绑定：报告仅引用 job 目录中的已落盘结果，减少“运行时不一致”。
- 通过可复现记录（输入 MD5、参数、阶段信息）与 job 目录实现审计与复盘。

边界说明：
- 报告是结果展示与归档载体，不替代学术论文的严谨验证流程。

## 与 microeco 2.0 的区别
- microeco 2.0：提供微生物组数据对象与方法组件（计算/可视化/整理等），偏“分析工具箱/框架”。
- 本系统：microeco 2.0 的上层应用，偏“流程化产品/交互式系统”：
  - 提供 UI（Shiny）、作业目录、结果固化与报告；
  - 提供受约束的解释链路与留痕；
  - 聚合多个模块产物形成可展示的 end-to-end pipeline。

结论：
- 本系统不是替代 microeco，而是让 microeco 更易用、更可复现、更适合交付展示。

## 与 BioIntelOS 类泛 AI 科研平台的区别
相同点：
- 都可能包含 AI 辅助解释、自动化流程与可视化展示。

不同点（不夸大、强调定位差异）：
- 领域聚焦：本系统专注微生物组常见流程（Alpha/Beta/Diff/ML/Network/KeyTaxa），方法与产物结构更“贴合领域习惯”。
- 解释约束：本系统的 LLM 输入被严格限制为结构化统计摘要与本地解释，且保存请求/响应留痕，强调“可审计、非因果、不可改结论”。
- 可复现交付：以 job 目录 + Quarto 报告作为交付单元，适合论文附录与答辩展示；泛平台更偏通用协作与多领域功能集合。
