# 论文大纲（PAPER OUTLINE）

## 中文论文题目（建议稿）
基于 microeco 2.0 与大语言模型的微生物组关键菌筛选、可信解释与可复现报告生成系统设计与实现

## 英文论文题目（建议稿）
Design and Implementation of a Reproducible Microbiome Key-Taxa Screening and Trustworthy Interpretation System Built on microeco 2.0 and Large Language Models

## 摘要结构（建议写法）
1. 研究背景与意义：微生物组研究中“从数据到可解释结论”的工作流复杂、重复成本高，且结果复现与展示存在工程门槛。
2. 研究目标：在不替代 microeco 2.0 的前提下，构建其上层应用系统，实现自动化再分析、关键菌筛选、受约束解释与可复现报告生成。
3. 方法与系统：基于 R Shiny + microeco 2.0 + Quarto；将差异分析、随机森林特征重要性、Spearman 共现网络中心性整合为 Key Taxa Score；引入“结构化统计结果约束”的 LLM 解释框架，明确非因果与不改变统计结论。
4. 实验与结果：以示例数据与真实数据（可选）验证系统可用性；给出 Alpha/Beta/Diff/ML/Network/KeyTaxa 输出与 HTML 报告；通过作业目录与可复现记录证明可追溯性。
5. 结论与展望：总结系统价值（流程标准化、可复现、可展示），讨论局限（探索性结果、样本量限制、LLM 解释边界）并提出后续方向（更多数据类型、参数化与性能优化等）。
6. 关键词（示例）：微生物组；microeco 2.0；关键菌；可复现性；R Shiny；Quarto；大语言模型；可信解释

## 绪论（第 1 章）
1. 研究背景：微生物组分析常见任务（多样性、差异、网络、机器学习）与工作流碎片化问题。
2. 问题陈述：结果复现成本高、分析与报告脱节、解释存在主观性与过度推断风险。
3. 研究内容与贡献边界：
   - 本系统是 microeco 2.0 的上层应用（workflow orchestration + UI + reporting），不替代 microeco。
   - ML 与网络结果定位为探索性发现，不作为因果证据。
   - AI 解释为受约束摘要，不做因果与机制结论。
4. 论文组织结构说明。

## 相关工作（第 2 章）
1. R 生态与微生物组分析工具：microeco、vegan 等在多样性/距离/置换检验中的常用做法。
2. 标志物筛选思路：差异检验、机器学习特征重要性、网络中心性等的常见用途与局限。
3. 可复现研究与报告：作业式输出目录、参数/版本记录、HTML 报告（R Markdown/Quarto）。
4. LLM 在科研解释中的应用与风险：幻觉、非因果推断、对原始数据的泄漏；引出“统计约束解释”的必要性。

## 系统设计（第 3 章）
1. 总体架构：Shiny 前端、分析编排、结果存储、报告渲染、AI 解释链路。
2. 作业（job）机制：每次运行独立目录与可复现记录。
3. 模块划分：Upload/Data Check/Parameters/Run Analysis/Alpha/Beta/Diff/Report 等。
4. 数据与产物规范：输入三表、输出 tables/figures/json/ai/report/logs。

## 方法实现（第 4 章）
1. 数据导入与标准化：样本/特征对齐、缺失与格式检查。
2. Alpha 多样性：microeco 计算与组间非参数检验（Shannon 为核心示例）。
3. Beta 多样性：Bray-Curtis 距离、PCoA、PERMANOVA（adonis2）。
4. 差异丰度：两组 Wilcoxon，多组 Kruskal-Wallis，FDR 校正与可视化（volcano）。
5. 随机森林：特征重要性与模型指标输出；样本量分级提示（探索性）。
6. 共现网络：Spearman 相关 + FDR 阈值筛边；中心性计算与可视化；强调相关不等于因果。
7. Key Taxa Score：差异证据 + ML 重要性 + 网络中心性归一化融合（加权平均）。
8. AI 可信解释：仅基于结构化统计 JSON 与本地规则解释文本；LLM 不得改变统计结论与不得推断因果机制；输出 Markdown/JSON 留痕。
9. Quarto 报告：模板化渲染，报告与产物路径绑定到 job 目录。
10. 可复现性记录：输入 MD5、参数、阶段时间戳与关键输出路径。

## 系统测试（第 5 章）
1. 功能测试：以示例数据跑通 Upload -> Data Check -> Parameters -> Full Workflow -> Report。
2. 异常输入测试：缺失列、样本不匹配、分组变量缺失、样本量过小、网络无边等情况的提示与稳定输出。
3. 结果一致性检查：关键产物文件存在性、统计阈值与摘要一致性（JSON/Markdown/报告间一致）。
4. 可复现性验证：同一输入与参数在同环境下可生成一致结构的 job 目录与记录文件。

## 结果展示（第 6 章）
1. 系统界面与流程截图（Upload/Data Check/Parameters/Run/Report）。
2. 核心结果示例：Alpha/Beta/Diff 图与表、ML 重要性图与指标、网络图与节点/边表、Key Taxa 排名表与柱状图。
3. 报告展示：`report.html` 的结构与关键段落（统计结果 + 受约束解释 + 可复现记录入口）。

## 讨论（第 7 章）
1. 系统定位：microeco 2.0 上层应用的价值与适用场景。
2. 统计与探索性结果的边界：多重比较、样本量、混杂因素、网络相关性误读风险等。
3. LLM 解释的边界与风险控制：不读原始表、仅用统计 JSON、不得因果推断与不得“升格显著性”。
4. 局限：参数固定、数据类型覆盖范围、计算性能、对 Quarto/环境依赖等。

## 总结与展望（第 8 章）
1. 总结：实现了可运行的端到端系统，支持关键菌筛选、受约束解释与可复现 HTML 报告生成。
2. 展望（不夸大）：更多统计与可视化可配置、更多数据类型与批次效应处理、规模化性能优化、解释模块的系统化评估等。
